# Руководство по ручному тестированию

Автоматические тесты в репозитории **изолированы**: они никогда не запускают движки, не открывают туннели и не меняют
системные сетевые настройки. Всё, что описано ниже, должен проверить человек на машине, где потеря связи допустима
(лучше всего на виртуальной машине или отдельном устройстве). **Не выполняйте эти шаги на машине, удалённый доступ к
которой зависит от её текущих сетевых настроек.**

Запускайте BYDLO из оболочки **без** `BYDLO_SAFE_DEV` (или используйте сборку из CI). Для отчётов об ошибках сохраняйте
`logs/bydlo.log` (путь к каталогу данных показан в Настройки → Дополнительно). Учётные данные из лога уже вырезаны, но
перед отправкой всё равно проверьте его.

## 0. Mock-режим (безопасно где угодно)

1. `dotnet run --project src/Bydlo.Desktop -- --mock`.
2. Подключения → *Демо-серверы (mock)*. Главная → Подключить: статус меняется «Подключение…» → «Подключено», таймер и скорость обновляются.
3. Настройки → Дополнительно → сценарий Mock = *Ошибка при подключении*: появляется баннер с ошибкой.
4. Сценарий = *Сбой через ~20 с*: статус становится «Переподключение…», затем снова «Подключено» (автопереподключение).
5. Включите Zapret / TgWsProxy на главной: оба показывают «Работает» независимо от туннеля.
6. Переключите темы (фиолетовая / светлая / OLED / системная) и язык (RU / EN); сузьте окно до ширины меньше 760 px — появится нижняя навигация.

## 1. Движки

- Инструменты → Движки: установите sing-box и Xray, ожидается статус «Готов».
  Проверка подмены: измените хеш в `engines/engines.lock.json`, пересоберите и установите — установка должна завершиться
  ошибкой целостности и ничего не оставить.

## 2. Режим локального прокси (без прав администратора)

Для каждого протокола, для которого у вас есть сервер (VLESS/REALITY, VLESS XHTTP, VMess, Trojan, SS, Hysteria 2, TUIC, SOCKS, WireGuard через sing-box):

1. Импортируйте через буфер обмена, файл и изображение с QR-кодом.
2. Подключитесь. Настройте браузер на SOCKS5 `127.0.0.1:2080`, откройте сайт проверки IP — IP должен быть адресом сервера.
3. В «Статистике» видна скорость в реальном времени (sing-box) или пометка «движок пока не сообщает трафик» (Xray).
4. Отключитесь — порт 2080 закрыт. Завершите процесс движка вручную во время подключения — появятся попытки переподключения.
5. Займите порт 2080 другой программой — подключение должно быть отклонено с понятным сообщением.

## 3. Режим TUN (администратор/root)

1. Настройки → Перезапустить от администратора (Windows) или запустите через sudo (Linux/macOS).
2. Главная → включите TUN, подключитесь. Все приложения идут через туннель; роутер и принтер в локальной сети доступны (если включён обход локальных сетей).
3. При включённом «Mesh-VPN диапазоны — напрямую» уже работающая mesh-VPN (например, Tailscale, ZeroTier, NetBird) продолжает работать.
4. Отключитесь — маршрут по умолчанию и DNS возвращаются в исходное состояние.

## 4. Нативные WireGuard / AmneziaWG / OpenVPN

1. Установите официальный клиент. Импортируйте `.conf` / `.ovpn`. Подключитесь с правами администратора.
2. Windows: во время подключения существует служба туннеля `WireGuardTunnel$bydlo-wg` (или аналог AmneziaWG), после отключения она удаляется.
3. Профили OpenVPN с `auth-user-pass` без сохранённых учётных данных должны показывать понятную ошибку (редактор учётных данных — в roadmap).

## 5. Zapret (проверяет только мейнтейнер)

1. Распакуйте официальный релиз Windows x64 и запустите с правами администратора. Нажмите Zapret на главной без захода в «Инструменты»: встроенная копия и `general.bat` должны выбираться автоматически. Проверьте также запуск без доступа к GitHub. Загрузка закреплённого релиза и папка пользователя остаются резервными вариантами.
2. Убедитесь, что не запущены другие `winws.exe` или GoodbyeDPI (иначе BYDLO откажется стартовать).
3. Выберите `general`, нажмите «Запустить». В логах вывод winws, статус «Работает». Проверьте Discord / YouTube.
4. Отредактируйте пользовательские списки, сохраните, перезапустите Zapret. Попробуйте другие стратегии и игровой фильтр.
5. Остановите — `winws.exe` завершён. Закройте BYDLO во время работы — при следующем запуске BYDLO предложит остановить оставшийся процесс.

### Linux / macOS и восстановление правил

1. Используйте отдельную VM со снимком. На Linux установите nftables, проверьте NFQUEUE; на macOS проверьте стандартные `com.apple/*` filter/rdr anchors и отсутствие слушателя TCP 21771. Запускайте BYDLO с root, но проверяйте трафик macOS от обычного пользователя.
2. Без ручной установки движка включите Zapret: Linux запускает nfqws, macOS — tpws. На Linux проверьте TCP/QUIC и оба пресета; на macOS — только IPv4 TCP 80/443. UDP, IPv6 и трафик root на macOS должны остаться без изменений.
3. До и после остановки сравните правила системы: появляется и удаляется только `inet bydlo_<id>` (Linux) или `com.apple/bydlo_<id>` (macOS). Общие таблицы, политики, чужие anchors и состояние PF других клиентов не должны меняться.
4. Завершите только дочерний движок: BYDLO должен снять правила до публикации ошибки/переподключения. Проверьте отмену запуска и ошибку применения правил. На Linux `queue bypass` пропускает трафик при отсутствии слушателя.
5. Принудительно завершите BYDLO. При следующем запуске **того же каталога данных** с root вне Mock/Safe Dev BYDLO снимает записанные правила; оставшийся процесс движка показывается отдельно в `ProcessJournal`. Без root очистка откладывается; не считайте её выполненной. Это восстановление при следующем запуске, не watchdog после SIGKILL.
6. При ошибке очистки `<data>/zapret/firewall.json` сохраняется для повтора. Не удаляйте журнал до ручной проверки. PF использует reference token (`-E`/`-X`), никогда `pfctl -d` и не заменяет корневой ruleset. Между получением PF-токена и его записью возможен сбой питания: anchor будет снят при восстановлении, но reference может потребовать ручного разбора; автоматическое глобальное выключение PF недопустимо.
7. Измените все три пользовательских списка, обновите/переустановите приложение и управляемую копию — записи в `<data>/zapret/lists` должны сохраниться. Старые списки из папки Flowseal мигрируют только при отсутствии целевого файла.

### Антивирус / карантин (Windows)

WinDivert может определяться как RiskTool/PUA. BYDLO проверяет наличие `winws.exe`, `WinDivert.dll`, `WinDivert64.sys`, `cygwin1.dll` и списков; при пропаже показывает сообщение о карантине/восстановлении, а не статус готовности. Сверьте источник релиза и `SHA256SUMS.txt`, изучите детали детекта в антивирусе и документацию upstream. Не отключайте защиту автоматически; BYDLO не добавляет исключения и не восстанавливает карантин. Для разработки достаточно сборки и тестов с фейками, скачивать бинарники на рабочую машину не требуется.

## 6. TgWsProxy

1. Инструменты → TgWsProxy → «Установить среду» (Python 3.9+ в PATH) или укажите готовый исполняемый файл `tg-ws-proxy`.
2. Запустите; нажмите *Открыть в Telegram* или скопируйте ссылку в Telegram Desktop — Telegram подключается через прокси.
3. «Новый секрет» — ссылка меняется, появляется сообщение о необходимости перезапуска.
4. Займите порт 1443 — запуск должен быть отклонён с сообщением о конфликте порта.

## 7. Системный прокси (Windows)

Включите Настройки → Дополнительно → *Включать системный прокси при подключении*, подключитесь в режиме локального прокси:
настройки прокси Windows указывают на 127.0.0.1:2080. Отключитесь (а также закройте BYDLO во время подключения) — прежние
настройки прокси восстанавливаются.

## 8. Проверка соединения

1. Подключитесь в режиме локального прокси (sing-box или Xray).
2. Главная → *Проверить соединение*: появляется карточка с внешним IP, страной и задержкой. IP должен быть адресом
   сервера, а не домашним.
3. Настройки → Подключение → *Сервис проверки IP*: выберите другой сервис и повторите проверку.
4. Отключитесь — карточка результата исчезает. В Mock-режиме кнопка отключена и показывает пояснение.
5. При ошибке сети или сервиса показывается понятный совет без технических подробностей.

## 9. Первый запуск и пустое состояние

1. Запустите с отдельным пустым каталогом данных (реальные настройки не затрагиваются):
   `$env:BYDLO_DATA_DIR = Join-Path (Get-Location) '.tmp/first-run'` и затем
   `dotnet run --project src/Bydlo.Desktop -- --mock`.
2. Должен появиться экран приветствия с выбором языка и темы. По умолчанию выбраны язык системы и системная тема.
3. Смените язык и тему, нажмите «Начать» (или «Пропустить»). Настройки применяются сразу.
4. Пока серверов нет, главная показывает приветствие и три карточки: «Ссылка или подписка», «Файл», «QR-код».
   Проверьте каждую: вставка ссылки, выбор файла и выбор изображения с QR-кодом.
5. После добавления сервера пустое состояние исчезает и появляется обычная кнопка подключения.
6. Перезапустите BYDLO с тем же `BYDLO_DATA_DIR` — экран приветствия больше не показывается.

## Отчёт об ошибке

Укажите ОС и её версию, версию BYDLO, движок и его версию, протокол, режим (прокси/TUN) и очищенный лог.

## Kill switch (#16)

Изолированные тесты `KillSwitchTests` проверяют конфигурацию IPv4/IPv6, независимость
исключений LAN/mesh, отсутствие прямого fallback, сохранение TUN при неудачных повторах,
снятие блокировки при ошибке запуска/остановки и поведение при сбое самого TUN.
Процессы и реальные сетевые интерфейсы в них не запускаются.

Мейнтейнер вручную, на отдельной тестовой машине с восстановлением доступа, проверяет:

- Предупреждение, подтверждение включения и применение после переподключения TUN.
- Отказ транспорта, все попытки переподключения и отключённый AutoReconnect:
  публичные IPv4/IPv6/DNS не выходят напрямую, выбранные LAN/mesh доступны.
- Восстановление транспорта без пересоздания TUN и без прямого интернет-доступа в паузе.
- Обычное отключение, аварийную кнопку, закрытие окна и завершение приложения:
  TUN и его временные маршруты/фильтры снимаются.
- Сбой BYDLO при работающем TUN, следующий запуск и восстановление с теми же правами;
  чужие VPN/mesh не завершаются. Отказ в доступе не удаляет запись из журнала.
- Собственное падение TUN: интерфейс показывает ошибку; это явно описанное ограничение защиты.

Автоматически эти сетевые сценарии не выполнять.
