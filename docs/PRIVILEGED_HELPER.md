# Привилегированная служба (#83)

Служба позволяет оставить интерфейс BYDLO без прав администратора. Она запускает
TUN sing-box, Zapret, AmneziaWG и OpenVPN из отдельного защищённого комплекта.
Без установленной службы сохраняется прежний запуск с повышенными правами.

| Платформа | Установка | IPC | Статус |
|---|---|---|---|
| Windows | Windows service `BYDLOHelper`, LocalSystem, UAC | named pipe, ACL и SID | ✅ проверено сопровождающим |
| Linux | systemd `bydlo-helper.service`, root, polkit/pkexec | Unix-сокет, SO_PEERCRED | 🧪 требуется ручная проверка |
| macOS Apple Silicon | launchd `online.bydlo.helper`, root, системный диалог администратора | Unix-сокет, getpeereid | 🧪 требуется ручная проверка |

## Установка и удаление

Откройте **Настройки → Дополнительно → Привилегированная служба** и нажмите
«Установить службу». Подтвердите системный запрос администратора. Текущие подключения
BYDLO перед операцией останавливаются. Служба доступна только пользователю, который
её установил: SID в Windows, UID в Unix. Для другого пользователя удалите службу
и установите её из его сеанса.

Релиз содержит отдельный каталог `helper/` и соседний `engines/`. CI проверяет архитектуру приложения и службы, а в архивах Linux и macOS проверяет права на запуск обеих программ. Для локальной
сборки оба каталога нужно подготовить так же, как в CI; обычный `dotnet build`
не устанавливает службу и не создаёт системные файлы.

Кнопка «Удалить службу» запрашивает права администратора, останавливает службу,
удаляет её регистрацию и собственный защищённый каталог. Запускайте удаление из
исходного каталога релиза, а не из установленной копии службы. После неудачной
установки тот же путь удаления очищает оставшуюся копию; перед повторной установкой
нужно завершить удаление. Ошибка остановки или удаления файлов не считается успехом.
Если BYDLO сообщает, что служба устарела, откройте новый релиз, нажмите «Удалить
службу», затем «Установить службу» и подтвердите оба запроса администратора.
BYDLO сверяет версию службы и отпечаток `engines.lock.json` перед запуском движка.

Linux требует systemd и установленный `pkexec` с агентом polkit. На macOS используется
`osascript` с системным подтверждением. Другие системы и Android не поддерживаются.
Драйвер OpenVPN DCO на Windows устанавливается отдельной явной операцией.

## Граница доверия и ограничения

IPC v2 — UTF-8 JSON с четырёхбайтовой длиной little-endian; максимум 1 МиБ на сообщение.
Операции: проверка доступности, запуск, состояние/журнал/трафик, остановка, переподключение,
список и закрытие активных соединений. Протокол не принимает команды, PID или пути к
исполняемым файлам. Рабочий каталог создаёт служба; клиентский путь игнорируется.

В Windows pipe запрещает сетевые подключения, разрешает доступ только SYSTEM и
разрешённому SID, не выдаёт пользователю право создавать экземпляры сервера.
Клиент проверяет владельца SYSTEM и путь процесса сервера до передачи секретов.
В Unix проверяются UID клиента и root на серверной стороне соединения; сокет доступен
только разрешённому пользователю. Каталоги и файлы службы записывает администратор/root,
обычный пользователь не может менять исполняемый комплект или контрольные суммы.

При установке администратор разрешает копирование именно этого релизного комплекта.
Его файлы получают SHA-256, сохранённые в защищённом манифесте. Служба сверяет полный
комплект при старте и перед запуском движков, включая DLL и стратегии; изменения,
дополнительные файлы и ссылки запрещены. Исходные архивы движков проверяются сборкой
релиза по `engines.lock.json`; установочный манифест фиксирует распакованные файлы.
Это не заменяет проверку происхождения самого релиза пользователем.

Пользовательские executable-пути, JSON-конфиги sing-box/Xray, SIP003-плагины, цепочки
и внешние наборы правил не доступны через службу. OpenVPN принимает ограниченный
список директив, сертификаты и ключи только inline; команды, плагины, вложенные конфиги,
внешние файлы и management запрещены. Для остальных сценариев удалите службу и
используйте прежний запуск с повышенными правами. Списки Zapret принадлежат отдельному
каталогу данных службы; списки из пользовательского каталога UI автоматически не копируются.
Когда Zapret запускается через службу, редактор списков в «Инструментах» отключён
и показывает предупреждение об этом ограничении. Для своих списков удалите службу
в «Настройки → Дополнительно» и запустите BYDLO с повышенными правами.
При запуске с повышенными правами и в Mock Mode редактор остаётся доступным.

Одна IPC-сессия владеет одним движком. Одновременно допускаются один основной туннель
и один Zapret, максимум четыре клиентских соединения. Обрыв IPC или отсутствие запросов
90 секунд останавливает принадлежащий сессии движок. После аварии службы используются
журнал процессов и восстановление собственных сетевых ресурсов. Секреты не возвращаются
в ответах; вывод проходит существующий LogRedactor, ошибки IPC возвращают только код.

`BYDLO_SAFE_DEV=1` запрещает установку, удаление, сервер и клиент до IPC/привилегированных
действий. В `--mock` интерфейс не использует службу и кнопки управления отключены.

## Проверки

`PrivilegedHelperTests` проверяет протокол в MemoryStream, ограничение размера,
обрезанные сообщения, версии/операции, запрет произвольных файлов/плагинов и опасных
OpenVPN-директив, SHA-256, владение сессией, конфликтующие аренды и блокировку разработки.
Движки, сервер IPC и системные службы тесты не запускают.

Мейнтейнер вручную проверяет на каждой ОС: установку и отмену системного диалога;
UI без повышенных прав; подключение/остановку каждого поддерживаемого движка;
отказ другому пользователю; отказ при изменении комплектного файла; завершение UI
и восстановление после аварии службы; переподключение и kill switch; удаление,
частично завершённую установку и повторную установку. Эти проверки агентом **не выполнялись**.

Документация платформ: [named pipe ACL](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights),
[SO_PEERCRED](https://man7.org/linux/man-pages/man7/unix.7.html),
[systemd.service](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html).
