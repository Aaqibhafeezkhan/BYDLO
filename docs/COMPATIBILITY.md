# Матрица совместимости (v0.1)

Обозначения: ✅ реализовано · 🧪 реализовано, но **ещё не проверено мейнтейнерами в реальной сети** · 🗓 запланировано · ❌ невозможно / не поддерживается

Большинство сетевых сценариев в v0.1 имеют статус 🧪: код написан и покрыт модульными тестами с фейками, но работу из конца в
конец нужно подтвердить по [руководству по ручному тестированию](TESTING.md). Мейнтейнер уже проверил в реальной сети на
Windows x64: Zapret (Flowseal) и встроенный TgWsProxy (✅), для TgWsProxy — включая долгий простой и сон/пробуждение
компьютера. Mock-режим работает везде, где запускается интерфейс.

| AmneziaWG 3.1.20260828 | Windows x64/ARM64 и Linux x64/ARM64: собственный процесс-хост upstream Go-библиотеки, без официального клиента и awg-quick. Windows: встроен подписанный Wintun 0.14.1. macOS пока не реализован. |
| OpenVPN 2.7.8 | Все шесть платформ: консольный движок. Windows: DLL и подписанный DCO 2.8.14 извлечены из закреплённого официального MSI; установка DCO и выделенного адаптера — отдельная команда с согласием и правами администратора. Linux/macOS: сборка со статическим OpenSSL 3.6.5; Linux также со статическим libcap-ng 0.9.6. |
| Нативный WireGuard | Официальный клиент, установленный пользователем; для userspace WireGuard доступен встроенный sing-box. |

Для AmneziaWG нужны права администратора/root; Linux использует `/dev/net/tun`, `ip` и, при DNS в профиле,
`resolvectl` с systemd-resolved. На Linux без systemd-resolved настройка DNS этим адаптером пока не поддерживается.
Маршруты по умолчанию добавляются как две половины `/1`, исходные default routes сохраняются; маршрут к каждому
серверу закрепляется до включения туннеля. Изменения привязаны к отдельному `bydlo-awg` и журналу восстановления.
Хуки `PreUp/PostUp/PreDown/PostDown`, `Table`, `SaveConfig` и DNS-домены в `.conf` отклоняются.
На macOS для AmneziaWG возвращается `NotImplemented`.

OpenVPN 2.7 не поддерживает Wintun. BYDLO использует DCO; TAP-профили и несовместимые с DCO параметры
на Windows не поддерживаются этой встроенной конфигурацией. Драйвер и адаптер остаются установленными после выхода;
для удаления используется диспетчер устройств Windows. Установка не выполняется при подключении, в Mock Mode или safety lock.
Unix-сборка отключает LZO/LZ4, PKCS#11, плагины и DCO: OpenSSL и libcap-ng не нужно доустанавливать,
но libc и системные инструменты настройки сети остаются зависимостями ОС. Автоматическое применение pushed DNS
для OpenVPN на Unix пока не реализовано; используйте настроенный системный DNS.
Нативные подключения AmneziaWG/OpenVPN и установка DCO требуют ручной проверки владельцем, автоматические тесты используют фейки.

## Cloudflare WARP (заметка по исследованию)

WARP основан на WireGuard. Для регистрации нужно обращаться к недокументированному клиентскому API Cloudflare (как это
делают сторонние инструменты вроде wgcf / warp-plus), условия и стабильность которого неясны. Поэтому v0.1 поддерживает
WARP только через импорт конфигурации WireGuard, созданной таким инструментом. Собственная регистрация — в roadmap,
после проверки лицензионных условий.

## Ограничения Zapret

- Windows ARM64: в закреплённом Flowseal-архиве есть только x64 WinDivert. Эмуляция x64 не заменяет ARM64 kernel driver; BYDLO честно возвращает `NotImplemented`.
- Linux: нужен root, установленный `nft` и поддержка NFQUEUE в ядре. Используется только nftables; fallback на iptables отсутствует. Очередь 21770 и метка 0x40000000 зарезервированы для BYDLO.
- macOS: нужен root, свободный TCP-порт 21771, активные стандартные `com.apple/*` filter/rdr anchors. BYDLO не переписывает `pf.conf`. Только локальный IPv4 TCP 80/443; UDP/QUIC, IPv6, трафик root и игровой фильтр не поддерживаются.
- Нативные пресеты BYDLO используют публичные опции upstream; они не копируются из проектов без лицензии и не эквивалентны всем стратегиям Flowseal.
- Пользовательские списки находятся в `<data>/zapret/lists/`. Приоритет установки: встроенная исправная копия → управляемая → папка пользователя. При обновлении приложения пользовательские списки не перезаписываются.
- Работоспособность обхода в конкретной сети проверяет мейнтейнер вручную.

## Kill switch

Опция выключена по умолчанию. В **Настройки → Дополнительно** прочитайте предупреждение,
подтвердите его и включите «Блокировать интернет при отключении VPN». Опция применяется
при следующем подключении **TUN через sing-box**. Для других движков подключение TUN с этой
опцией отклоняется; режим локального прокси не меняется.

Отдельный процесс sing-box держит `auto_route` + `strict_route` и передаёт интернет-трафик
в локальный SOCKS5-порт транспортного процесса. При падении транспорта и во время его
перезапуска TUN остаётся активным; прямого резервного выхода в интернет нет. После
исчерпания попыток переподключения блокировка сохраняется до явного отключения.
LAN (IPv4, IPv6 link-local и ULA) и mesh-диапазоны исключаются согласно настройкам маршрутизации.
Прямые домены, CIDR, процессы и режим «только выбранные домены» при этом игнорируются.

Кнопка **«Выключить kill switch и отключиться»** доступна в настройках без раскрытия
дополнительных параметров. Обычное отключение и закрытие окна также останавливают TUN.
После сбоя BYDLO следующий запуск пытается завершить только оставшийся TUN-процесс из
журнала BYDLO с проверкой PID, имени образа и времени запуска. Если не хватает прав,
нужен перезапуск с прежними правами и эта же кнопка либо очистка оставшихся процессов.
Чужие VPN и mesh-клиенты не затрагиваются. Mock-режим и safety lock запрещают такую очистку.

**Ограничение:** защита действует, пока жив отдельный TUN-процесс. Его собственный сбой,
принудительное завершение или изменение маршрутов сторонним ПО может открыть прямой доступ.
Это не постоянная блокировка на уровне ОС. Сетевое поведение и снятие маршрутов после
аварии требуют ручной проверки на каждой ОС; агенты и CI её не выполняют.

Схема: [TUN / strict_route](https://sing-box.sagernet.org/configuration/inbound/tun/),
[SOCKS outbound](https://sing-box.sagernet.org/configuration/outbound/socks/).

Автоподбор Zapret доступен в «Инструменты → Zapret»: Windows — аргументы winws из найденных BAT,
Linux/macOS — нативные пресеты. Стандартные HTTP/TLS-проверки Test Zapret 1.10.3 перенесены
в BYDLO; интерактивный скрипт не запускается. Проверка только по явному действию пользователя,
с правами администратора/root, curl и возможностью отмены. Область измерений и ограничения:
[автоподбор в TESTING.md](TESTING.md#автоподбор-zapret).
